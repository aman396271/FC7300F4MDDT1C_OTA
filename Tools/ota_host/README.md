# FC7300 UART OTA host

This directory contains one shared upgrade stack:

```text
CLI / PySide6 GUI
        |
UpgradeController
        |
OtaClient
        |
Transport (SerialTransport now; CAN/ISO-TP/UDS later)
```

The tool accepts only `.pkg` files generated by `Tools/pack_hw_ota_image.py`
or `Tools/build_ab_demo.py`. It never accepts Intel HEX and never programs NVR.
If the device reports `OTA_EN=0`, the operation is rejected with an explicit
instruction to configure NVR through the offline programming flow.

## Install and run

From the project root:

```powershell
python -m pip install -r Tools\ota_host\requirements.txt
python -m Tools.ota_host.cli --list-ports
python -m Tools.ota_host.cli --port COM7 info
python -m Tools.ota_host.cli --port COM7 upgrade out\ab_demo\app_b.pkg
python -m Tools.ota_host.gui
```

After a successful FINISH, both interfaces display `WAIT_POR`. Perform a real
power-on reset before expecting the newly committed physical Bank to become
active.

## Version source

Edit only `Tools/ota_versions.json`. `Tools/generate_ota_version.py` generates
`Include/ota_version_autogen.h`; the ELF header consumes that value and the
packer reads the version back from the linked header. Runtime text, ELF,
package and hardware indicator therefore use the same value.

The manifest can contain named test profiles while remaining the only version
source for each build. Build both initial POR-demo variants, or a single
profiled package, with:

```powershell
python Tools\build_ota_package.py A
python Tools\build_ota_package.py B
python Tools\build_ota_package.py A --profile return_a_v3
```

## Automated tests

```powershell
python -m pytest Tools\ota_host\tests -q
python Tools\test_fc7300_nvr_config_tool.py
```

The in-memory simulator covers framing, retry/idempotency, sequence and offset
errors, package validation, complete upgrade, cancellation, version rejection,
disabled OTA and FINISH CRC failure without requiring hardware.

The GUI shows a green connected badge and changes `Connect` to `Disconnect`
after HELLO/GET_INFO succeed. START_UPDATE performs a synchronous full inactive
Bank erase on the MCU, so the GUI uses an animated indeterminate progress bar
and an elapsed timer during that phase. Percentage and transfer speed begin
when DATA transmission starts.
